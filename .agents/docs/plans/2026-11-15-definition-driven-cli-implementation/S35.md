## Requirements (copied from the specification)

### 4.5 Validation

`backlog validate` checks with Ajv (D-62), in this order: each schema file against the published JSON Schema specification; the team file, every team in it at once, against `team-file.schema.json` and `team-rules.schema.json` with Ajv, and the rules by the checks of [team-rules-spec.md](../2026-11-14-definition-driven-cli/team-rules-spec.md) section 11; the user item definition against `item-definition.schema.json`; every item against `item.schema.json` and the definition that applies (every required field set, every value of its type); every item of a team against its team's rules. Each problem is reported with where it is, why, and what would fix it (D-49, ruling R11). A team command validates the team file before it acts; any finding in any team stops every team command (Q12-4). The file's SHA is kept in the configuration and a valid result is reused for 24 hours (rulings R21, R22).

## 5. Validation

`backlog validate` checks that `redaction_rules` fits the schema, that every `find` is valid RE2 syntax, and that every name in `properties` is a base property or a field of some item definition of the repository. A finding is reported with the rule (`id` or place), the reason and the fix.

- **D-49.** `backlog validate` checks what people write by hand: the team file (every team in it, with its rules and its item definition, the whole file at once), the user item definition, and the schema files. The team file and the user item definition are checked against the schema files; the schema files are checked against the published JSON Schema specification. Every item is checked against the definition that applies to it (every required field set) and, for an item of a team, against the team's rules.

## Scenarios (BDD)

- *U-VAL-1. Given valid files. Then exit 0.
- *U-VAL-2. Given a schema file that is not valid JSON Schema 2020-12. Then it is reported.
- *U-VAL-3. Given a team file with two teams, one with a broken rule. Then the whole file is reported invalid, the problem named with its team, rule, reason and fix.
- *U-VAL-4. Given a user item definition that does not fit `item-definition.schema.json`. Then it is reported.
- *U-RED-5. `backlog validate` reports a redaction rule whose `find` is not valid RE2 syntax, and a `properties` name no definition declares.

## Session 1: implement (at most 30 minutes)

Work only from this file. Do not read the whole specification; everything this slice needs is above.

1. Load the skills by their installed names: `test-driven-development`, `verification-before-completion`, `systematic-debugging` (only when a test fails for a reason you do not understand), `requesting-code-review`, `ponytail`.
2. Create a local branch from the head of `simplify/pr3-review`: `git switch -c slice/S35 origin/simplify/pr3-review` (after `git fetch`). Do not push.
3. **Scenarios first (BDD).** Write each scenario of "Scenarios" in `features/validate.feature` as Gherkin (`Scenario:`, `Given`, `When I run`, `Then`), reusing the steps of `features/steps/cli.js` and adding a step there only when none fits. Run `node --test --test-name-pattern "<scenario name>" .agents/test/features.test.js`; each must fail. Commit: `git commit -m "S35: failing scenarios"`.
4. **Unit tests (TDD).** Write each test of "Unit tests" in the named test file. Run `node --test <that file>`; every new test must fail for the reason the test states. Commit the failing tests: `git commit -m "S35: failing tests"`.
5. **Code.** Write the smallest code that makes the tests and scenarios pass, in the files of "Files" only. An existing test that asserts the old behaviour this slice replaces is updated in the same commit and named in the hand-off; no other file outside "Files" changes. Follow the interfaces exactly (names, parameters, return shapes). Use the libraries named; never hand-build what a library does.
6. **Run.** The slice's test file, then `npm test`, then `npm run check`, then the private-details guard (`node --test .agents/test/no-private-details.test.js` with the deny-list variable the session is given). All pass.
7. **Self review.** Run `requesting-code-review` on your diff against "Requirements" and "Interfaces", then `ponytail` on the same diff: remove every line the tests do not need, every option nobody asked for, every comment that repeats the code. Rerun step 6.

9. **Hand-off.** Write the hand-off below into the Handoff section of this slice's backlog item.

Stop rules: if 30 minutes pass, or a file outside "Files" must change, or a slice this one depends on is not merged, stop, commit what passes, and write the hand-off with status `BLOCKED` and the reason. Never widen the slice.
