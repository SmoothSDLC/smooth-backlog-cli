# Task 22: Foreign references are only checked for their form (B21c)


## 1. Goal & Scope

Goal: a foreign reference `owner/name#seq` is checked only to be well formed: `new --depends-on` and `update --set-depends-on` accept one that names no item, the cycle walk through other repositories and the refusal of a publication whose foreign reference does not resolve are removed, and `foreignItem` returns null for an unreadable foreign file instead of throwing.

Out of scope: references inside the own folder (existence and cycles stay); the team commands' reading of foreign items (`foreignRaw` of `src/team/item.js`, unchanged); the guards of the own folder (Task 21).

2. Given an item, When `backlog update <item> --set-depends-on acme/lib#7` runs, Then exit 0 likewise. (source: "`backlog update <item> --set-depends-on acme/lib#7` likewise (R24-02 user side)")
3. Given `acme/lib#x` or `acme#7`, When `new --depends-on` runs, Then it is refused (these are not foreign forms, so they fall to the own-folder check: `--depends-on: no item 'acme/lib#x' in this backlog`, exit 1). (source: "`acme/lib#x` and `acme#7` are refused")
4. Given two items whose foreign references would form a cycle through another repository, When either is written or published, Then nothing is refused (the cycle is not walked); a cycle inside the own folder is still refused with today's text. (source: "a cross-folder dependency cycle is no longer walked")
5. Given a publication whose foreign reference does not resolve, Then it is not refused. (source: "a publication whose foreign reference does not resolve is not refused")
6. Given a foreign item file that cannot be read (corrupt JSON), When `backlog next` or `backlog list` prints the dependency, Then the line is `⛓ depends on <id> (no such item in the backlog repository)` and nothing throws. (source: "an unreadable foreign item file shows as `(no such item in the backlog repository)` in `next` and `list` and never throws")
