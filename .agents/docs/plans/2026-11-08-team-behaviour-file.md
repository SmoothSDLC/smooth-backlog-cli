# Team Behaviour File Implementation Plan

> **For agentic workers:** Implement this plan phase by phase, tests first. Each phase leaves the full suite, `npm run check`, both BDD locations and the private-details guard green before it is committed. Execution of a phase starts only when the open owner questions it depends on are answered (listed below).

**Goal:** Every behaviour a team enforces comes only from the team behaviour file (the team's entry in `teams.json` and its workflow definition). The CLI reads and applies the file with a generic enforcer, hard-codes no behaviour pattern, and the user commands enforce nothing.
**Architecture:** Four JSON Schema files and shipped templates define the file; one validator checks it; one generic enforcer evaluates a step request against the item, the actor and the team entry; team commands own their code path; user commands carry no team vocabulary; an old definition migrates once or fails with a clear message.
**Tech Stack:** Node 24+ ESM, node:test, Gherkin features on the repository's existing runner, JSON Schema 2020-12.
**Spec:** 2026-11-08-team-behaviour-file/03-spec.md

## Global Constraints

- The owner principle of 2026-11-08 and the two personas (the user, the agents) in AGENTS.md. User commands refuse nothing and dictate nothing; a user who wants enforcement defines a team named `user`.
- No aliases, no backward compatibility, one behaviour per command, team behaviour only under `backlog team`, every command and subcommand documented.
- This repository is public: no private names anywhere (AGENTS.md, information security). Run `.agents/test/no-private-details.test.js` before every commit that touches a document.
- All CLI code lands on branch `simplify/pr3-review`.
