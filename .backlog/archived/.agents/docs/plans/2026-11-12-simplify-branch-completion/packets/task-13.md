# Task 13 packet: `backlog update` and `backlog done` on a team item with `--show-all` (B18a)


## 1. Goal & Scope

Goal: `backlog update <item> ... --show-all` and `backlog done <item> --show-all` change an item of a team like any item (no rule runs, no value is checked against the team's definition), write one history entry `{ at, by, session, step, changes, note }` with the note `--show-all on an item of team <t>`, keep every byte of the item outside the changed keys, `updated`, `updated_by`, the body and the new entry; `--set <field>=<value>` writes a field of a team item; and the user commands' claim, release and close refuse nobody and apply no work-in-progress limit and no dependency gate.

Out of scope: `move`, `archive`, `import`, `clean`, `new --split-from` on team items and the deletion of `src/shared/team-items.js` (Task 14); the order per owner in the index (Task 16); deleting `wip-limits.js`, `seam.js` and the `team?.` hooks of `update.js` (Task 28: leave the `team` parameter of `update.run` and its hooks as they are); `--branch` stays refused.

The run kind `user-set` means: the user command `backlog update 90 --set holder=member-3` with the user identity `alice` (the test sets `SMOOTH_BACKLOG_CLI_AGENT=alice`), with `--show-all` when `show_all` is true.

Unit-level scenarios (from the spec's cases):
- Given a team item, When each option runs with and without the flag (`--claim`, `--release`, `--close`, `--status`, `--append`, `--priority`, `--seq`, `--set`, and `backlog done`), Then without it exit 1 `❌ no phase '<item>' (create it with backlog new)` and nothing written; with it exit 0, the item changed, one history entry.
- Given a team item with status `done`, fields `priority`, `stage`, `owner`, `events` and `phase`, its fields in an order unlike any definition, When `backlog update <item> --append "x" --show-all`, Then every byte of the file is as before except `updated`, `updated_by`, the body and the new history entry (Review Focus 4 of the plan).
- Given a team item, When `backlog update <item> --set a=1 --set tags=["a","b"] --show-all`, Then one history entry whose `changes` names both keys, `a` is the number 1, `tags` the list.
- Given an item without a team, When `backlog update <item> --set a=1`, Then exit 1 and stdout is exactly `❌ --set is for items of a team; the options of backlog update name the fields of an item without one`.
- Given a team item, When `--set slug=x` (or any envelope key), Then exit 2 and the message names the key and, when an option sets it (`--name` for `name`, `--seq` for `seq`), that option.
- Given an item held by `alice`, When `backlog update 1 --claim bob` runs, Then exit 0 and `claimed_by` is `bob`; a claim over a work-in-progress limit and a claim of an item with an unfinished dependency exit 0 too.
