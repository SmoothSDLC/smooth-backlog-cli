## 3. BDD Acceptance Criteria

The scenario named by the BDD plan (section 2.4 row above) has no feature file; Given/When/Then at command level (`cli(...)` in a consumer repository):

1. Given a git repository whose root holds `.smooth-backlog.json` (`{"backlog_repository": ".backlog"}`) and no `.backlog/config.json`, When `backlog list`, `backlog new --name x`, `backlog team query --team t`, `backlog setup` and `backlog team validate --team t` run, Then each exits 2, standard error is `❌ backlog: the backlog configuration is the old root file .smooth-backlog.json; move it to .backlog/config.json`, and nothing is written (no `.backlog/`, no item, no clone; `git status --porcelain` unchanged).
2. Given the same repository, When `backlog --help`, `backlog list --help` and `backlog --version` run, Then they print as before and exit 0 (no configuration is read).
3. Given the repository holds both files, When `backlog list` runs, Then `.backlog/config.json` is read and the root file is ignored (no stop).
4. Given a repository with `.backlog/config.json` only, Then nothing changes (every existing test passes with the rewritten fixtures).
5. Given the five rewritten test files, Then none of them writes `.smooth-backlog.json` except the stop tests of this task, and `grep -rn "smooth-backlog.json" src` prints only the constant naming the file in the stop.
