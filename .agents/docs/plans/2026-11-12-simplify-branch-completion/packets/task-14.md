# Task 14 packet: `move`, `archive`, `archive done`, `import`, `clean`, `new --split-from` on team items (B18b)


## 1. Goal & Scope

Goal: `move`, `archive`, `archive done`, `import`, `clean` and `new --split-from` act on an item of a team only with `--show-all` (without it a team item is not seen and never touched), each team item they change gets one history entry with the note `--show-all on an item of team <t>` and the command word as step, an unfinished team item needs `--force` to be archived, and `src/shared/team-items.js` is deleted.

Out of scope: `update` and `done` (Task 13); the order per owner and the index entries `clean` leaves behind (Tasks 16 and 17: `clean` keeps dropping the branch's index list as today, the next read re-adds live items, so this task asserts on files, not on index order); `move --to-repository` (Task 20 removes it: do not extend it to team items); the old team code (Tasks 27-28); `--show-all` on `fields`, `setup`, `upgrade` (refused as an unknown option, exit 2).

## 3. BDD Acceptance Criteria

No scenario of this task's own in a feature file: its scenario is Task 15's (`features/show-all.feature`, BDD plan section 2.5: "a new features/show-all.feature | B18 | a person lists without and with `--show-all`, and archives the item of a team that no longer exists"). Unit-level Given/When/Then (the spec's cases; the texts below are the existing refusal wording of each command on the head, which stays):

- Given a branch `main` with user item `u` and team item `t` (team `parallel`, status `ready`) and a branch `feature` on the origin, When `backlog move t --to-branch feature` runs, Then exit 1, stdout `❌ no item '<t>' in the backlog of <repo>` and nothing is written. When `backlog move t --to-branch feature --show-all` runs, Then exit 0, the item's `branch` is `feature`, every other byte outside `updated`, `updated_by` and the history is as before, and the history has one new entry `{ by: <user>, step: 'move', changes: { branch: ['main', 'feature'] }, note: '--show-all on an item of team parallel' }`. `move --all-open-of-branch main --to-branch feature` follows the same rule per item.
- Given a team item closed with the team's own word `accepted`, When `backlog archive t --show-all` runs, Then exit 1 and stdout is the team variant of the refusal (section 4 fixes the text); When `backlog archive t --show-all --force` runs, Then exit 0, the file is under `archive/phases/` with status `accepted` and one history entry with step `archive`. Without `--show-all` exit 1 `❌ no phase '<t>'` (the existing test `archive does not see a team item ...` stays).
- Given an item without a team that is not closed, When `backlog archive <item>` runs without `--force`, Then the refusal is unchanged: `❌ <slug> is '<status>', not finished (closed or done) — finish it or pass --force`.
- Given two closed team items and one closed user item, When `backlog archive done` runs, Then only the user item is archived and the team files are byte-identical; with `--show-all` all three are archived and each team item has an `archive` entry.
- Given an open team item on branch `feature`, When `backlog import --branch feature` runs, Then it stays on `feature`; with `--show-all` it moves to `main` with one `move` entry; with `--higher --show-all` it is also placed first (`update <slug> --priority 0 --show-all`, one more entry, step `update`).
- Given a user item and a team item on the branch, When `backlog clean` is confirmed with `yes`, Then the user item file is gone, the team item file is still there and the output says `✅ 1 items removed from branch main`; with `--show-all` both files are gone and the output says `✅ 2 items removed from branch main`. `clean` no longer refuses a folder that holds team items.
- Given a team item `t`, When `backlog new --split-from t --name child --depends-on none` runs, Then exit 1 `--split-from: no phase '<t>'` (existing); with `--show-all` it exits 0, the new item has no team and `parent` is the parent's number, and the parent has one history entry `{ step: 'new', note: '--show-all on an item of team parallel spawned sibling <slug>' }`.
