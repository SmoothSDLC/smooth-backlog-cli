# Where the backlog is used: the impact list

Every place in the Cody topology that uses the backlog, reads its items or describes how to use it. An item that changes
the backlog CLI, its skill, an item field, a command or the workflow the CLI enforces carries the validation
requirement below, and is not closed until it is met.

**Validation requirement (NFR) on every item that affects the backlog CLI:** before the item closes:
- Every impact area below that the change touches is updated in the same Cody 2.0 pull-request set.
- Each touched area's check passes.
- This list is updated in the same change: an area added, changed or removed, or its paths corrected.

**Keeping it current.** The file-by-file inventory is generated by
`tools/backlog-impacts/inventory.py` in the topology repository, and kept there as
docs/architecture/Cody/backlog-impacts-inventory.json. That repository is private, and this one is public, so only the
areas and their checks are listed here.

When an inventory run finds a file in no area below, the area list is wrong: add the file's area here.
