# @smoothsdlc/smooth-backlog-cli 1.0.1

> Historical verification record. These versions, workflow runs, and download URLs
> document the artifact tested at the time. For supported installation and current
> paths, read root README.md and .agents/docs/development.md.

The complete branch-aware backlog CLI is published to GitHub Packages. It includes
GUID item identity, active priorities, task and acceptance-criteria lists,
new/open/done/archived states, branch isolation and transfer commands, JSON output,
interactive creation, four agent integrations, and controlled self-updates.

Version 1.0.1 corrects GitHub Packages login guidance for npm 9+ and adds real
published-version upgrade verification to the release workflow.

Requires Node.js 24+, npm, and Git. Authenticate with a GitHub personal access token (classic)
with `read:packages` when npm login requests a password:

```sh
npm config set @smoothsdlc:registry https://npm.pkg.github.com
npm login --scope=@smoothsdlc --auth-type=legacy --registry=https://npm.pkg.github.com
npm install --global @smoothsdlc/smooth-backlog-cli@1.0.1
backlog --version
```

The [release workflow](https://github.com/SmoothSDLC/smooth-backlog-cli/actions/runs/38990685530)
passed all 14 jobs. Linux, macOS, and Windows were each checked with Node 24 and 26.
Every combination downloaded the published package using a fresh npm cache,
matched its integrity to the published tarball, and passed 29 CLI command checks.
Every combination also installed published 1.0.0 and passed 31 checks through a
real feed-based upgrade to 1.0.1, preserving item GUIDs and refreshing integrations.

[Source CI](https://github.com/SmoothSDLC/smooth-backlog-cli/actions/runs/38990582188)
also passed the six-platform/runtime matrix and generated-skill validation.
The local suite passed all 51 tests. See the
[complete verification evidence](https://github.com/SmoothSDLC/smooth-backlog-cli/blob/main/.agents/docs/releases/1.0.1-verification.json)
for job URLs, runtime versions, and artifact integrity.

## Local verification of the actual published package

The [registry export workflow](https://github.com/SmoothSDLC/smooth-backlog-cli/actions/runs/38991111061)
downloaded the existing 1.0.1 package from GitHub Packages, verified its registry
integrity, and attached that exact tarball to this public release. No rebuild was
used. Download it without npm registry credentials:

```sh
curl -fL -o smoothsdlc-smooth-backlog-cli-1.0.1.tgz https://github.com/SmoothSDLC/smooth-backlog-cli/releases/download/v1.0.1/smoothsdlc-smooth-backlog-cli-1.0.1.tgz
npm install --global ./smoothsdlc-smooth-backlog-cli-1.0.1.tgz
```

That asset was downloaded and installed in the agent's Linux workspace with Node
24.19.0. Its SHA-512 matched the original release evidence. The full 51-test suite
passed with zero failures or skips against the installed package code and templates,
using only the test harness from a fresh public clone of tag v1.0.1. An additional
27 installed-CLI checks and all generated-skill validations passed. Hash checks
confirmed all 24 original installed files remained unchanged during verification.
