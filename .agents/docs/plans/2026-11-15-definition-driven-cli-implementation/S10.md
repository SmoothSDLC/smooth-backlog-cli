## Requirements (copied from the specification)

### 4.1 The backlog location

The backlog location is always a git repository: the current repository (`.backlog`), or a repository outside the current repository's folder named by the configuration (D-44). A command pulls the backlog before it acts, reading commands included. A command that changes the backlog commits only the files the CLI changed (items, the index, the number record), never other changed files of the repository, and pushes only the commits the CLI made, unless `push-backlog-updates` is false (D-76 and D-77). When the push is refused, only the command's own commit is taken back, a person's own commits and edits stay, and the command exits 3. A team command publishes its own commit alone and runs again when what it read changed upstream (Q12-2). No output names a file or folder of the backlog.

- **D-76.** `.backlog/config.json` keeps the key `push-backlog-updates`: true by default (every change is pushed); a user can set it to false. (An earlier lead decision to remove the key is archived.)

- **D-77.** A command commits only the files the CLI changed, never other changed files of the repository, and pushes only the commits the CLI made. Decision 44 is read with this.

- **Q12-2**. A team command publishes only its own commit; a person's unpushed commits stay local.

## Scenarios (BDD)

- U-SYNC-1. The backlog is pulled before a command acts; a change is committed and pushed before it exits.
- U-SYNC-2. A refused push takes back only the command's own commit, exit 3; a person's commits stay.
- *U-SYNC-5. Given another file of the repository is changed and not committed. When `backlog new ...` is run with the backlog inside the repository. Then the CLI's commit holds only `.backlog` files, and the other file stays changed and uncommitted.
- *U-SYNC-6. Given a person's own commit not yet pushed. When `backlog new ...` is run. Then only the CLI's commit is pushed; the person's commit stays local.
- *U-SYNC-7. Given `push-backlog-updates` false. Then the CLI commits and does not push.

## Interfaces

- `publish({root, paths, message}, config) -> {commit, pushed}`: stages exactly `paths`, commits, and pushes only that commit (`git push origin <commit>:refs/heads/<branch>`) unless `push-backlog-updates` is false. User commands and team commands both use it.

## Unit tests (TDD)

- `other files stay`: an uncommitted change to `README.md` stays uncommitted after `backlog new ...`.
- `person's commit stays local`: a person's unpushed commit is not on the remote after `backlog new ...`.
- `push off`: with `push-backlog-updates: false` the commit exists locally and the remote is unchanged.

## Session 1: implement (at most 30 minutes)

Work only from this file. Do not read the whole specification; everything this slice needs is above.

1. Load the skills by their installed names: `test-driven-development`, `verification-before-completion`, `systematic-debugging` (only when a test fails for a reason you do not understand), `requesting-code-review`, `ponytail`.
2. Create a local branch from the head of `simplify/pr3-review`: `git switch -c slice/S10 origin/simplify/pr3-review` (after `git fetch`). Do not push.
3. **Scenarios first (BDD).** Write each scenario of "Scenarios" in `features/storage.feature` as Gherkin (`Scenario:`, `Given`, `When I run`, `Then`), reusing the steps of `features/steps/cli.js` and adding a step there only when none fits. Run `node --test --test-name-pattern "<scenario name>" .agents/test/features.test.js`; each must fail. Commit: `git commit -m "S10: failing scenarios"`.
4. **Unit tests (TDD).** Write each test of "Unit tests" in the named test file. Run `node --test <that file>`; every new test must fail for the reason the test states. Commit the failing tests: `git commit -m "S10: failing tests"`.
5. **Code.** Write the smallest code that makes the tests and scenarios pass, in the files of "Files" only. An existing test that asserts the old behaviour this slice replaces is updated in the same commit and named in the hand-off; no other file outside "Files" changes. Follow the interfaces exactly (names, parameters, return shapes). Use the libraries named; never hand-build what a library does.
6. **Run.** The slice's test file, then `npm test`, then `npm run check`, then the private-details guard (`node --test .agents/test/no-private-details.test.js` with the deny-list variable the session is given). All pass.
7. **Self review.** Run `requesting-code-review` on your diff against "Requirements" and "Interfaces", then `ponytail` on the same diff: remove every line the tests do not need, every option nobody asked for, every comment that repeats the code. Rerun step 6.
8. **Commit** with the message `S10: Commit only the CLI's files, push only its commits` and the repository's agent identity, no trailers.
9. **Hand-off.** Write the hand-off below into the Handoff section of this slice's backlog item.

Stop rules: if 30 minutes pass, or a file outside "Files" must change, or a slice this one depends on is not merged, stop, commit what passes, and write the hand-off with status `BLOCKED` and the reason. Never widen the slice.
