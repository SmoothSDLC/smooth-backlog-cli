# Task 21: The guards look at the own folder (B21b)


## 1. Goal & Scope

## 3. BDD Acceptance Criteria

BDD plan section 2.3 rows, quoted: "a person's unpushed commit of another folder in the backlog clone stays local" is part of the chapter 04 section 6 list ("a team re-run drops only the command's own commit and publishes only that; a person's unpushed commit stays local and an uncommitted change is kept (question 2 of round 12) | B15 | team-concurrency" and "upstream changed only another repository folder: the team command is not run again, and only its own commit is published | B15 | team-concurrency"). Section 2.1: "R24 (own folder) | 2 | update 1 (R24-01), new 1 (R24-02) | B08 in the evaluator; B21 through the commands with a real foreign folder". No feature file is assigned. Given/When/Then:
1. Given the backlog clone holds an unmerged entry (a conflict left by an autostash) under another folder `other/repo`, When `backlog new`, `update`, `archive`, `list` run for `acme/app`, Then each succeeds (today each stops with `has unresolved conflicts after updating from`). (source: "a conflict in another folder of the clone no longer stops the command")
2. Given a person's unpublished commit that touches only `other/repo` in the backlog clone (backlog kept in its own clone), When a user command publishes, Then it is not refused; the commit is published with the branch as today. When a team command publishes, Then the commit stays unpushed and the team command's commit is the only one pushed. (source: "a person's unpublished commit in another folder no longer stops the command; a team command leaves it unpushed")
3. Given an unmerged entry or a conflict marker inside `acme/app`'s own folder, Then the command still stops with today's text `<home> has unresolved conflicts after updating from <ref> (<files>); nothing was read, changed or pushed. Resolve them (...), then run the command again`. (source: "a conflict inside the folder still stops with today's text")
4. Given the pull's rebase stops on a conflict at `other/repo/phases/001-x.json` (upstream and a person's local commit changed it), When a command of `acme/app` publishes, Then the rebase is aborted, the command's own commit stays local, exit 3, and standard error is `❌ backlog: other/repo/phases/001-x.json outside acme/app conflicts with upstream; this command changes only its own folder: resolve the conflict in the backlog clone and run it again`. (source: "keeps its own commit local and stops with exit 3")
5. Given a scratch repository with `b/y` unmerged, When `git commit --only -- a/x` runs, Then exit 0 (the test pins the git behaviour the narrowing depends on). (source: "The commit with `--only` over the folder's own paths succeeds while another folder has unmerged entries")
6. Given an unpushed team item in the clone and upstream numbers racing, When a user command's publication renumbers or repairs conflicts, Then the unpushed team item file is byte-identical afterwards (the added test). (source: "never renumbers or rewrites an unpushed team item of the same clone")
